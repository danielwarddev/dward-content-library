# Who is this for?

Ideal customer (any or all):

- Aware of Copilot but underutilizing it
- Worried they are "missing something" with AI and want to make sure they get all the value they can out of it
- Instead of waiting over a longer period of time, want their devs to quickly upskill on AI coding tools
- Want to have responsible AI adoption and avoid poor quality AI code

Enterprises who have adopted or will soon adopt GitHub Copilot as their AI coding assistant. This workshop is designed to give these companies a head start on effective use out of GitHub Copilot (reword: 2 purposes - jumpstart to speed up learning and avoid the unfamiliar period that causes defects). This includes both speeding up current development work, as well as avoiding low quality AI output, avoiding quick production defects.

It is targeted at developers, and while it's designed so that even developers who have experience with AI tools get value out of it, it will start out assuming zero knowledge to ensure all participants are on the same level.

# Goals

By the end, attendees should be:

- Familiar with the features of GitHub Copilot and how to use them
- Understand at a conceptual level what AI does well and what it doesn't in order to know when to and not to use it
- Able to to use AI confidently and deliberately in workflows of planning, prompting, verifying, and iterating
- Confident with their AI usage to do effective work more quickly

# Outline 

The workshops will use an example project, rather than a real production use case. Attendees will be given a web app as a starting point, with a scenario of having just inherited it from the previous team. It is a legacy app, on an old version and without any tests. They know how the app works in general, but not how the codebase itself works. This demo app is intended to make it easy to focus on the AI learning, rather than any actual language or framework learnings, so that teams can quickly take the knowledge back to their real projects.

Attendees will use AI to help learn about and document the project, add characterization tests, and create an upgrade plan. They'll then execute the plan in small batches, learning how to verify worked correctly as they go. After the upgrade is complete, a new feature will be added to the app.

This workshop is spread out over 6 weeks. Including time spent in the workshop meetings themselves, attendees are recommended to spend about 3-5 hours per week on the overall content. This balances the AI learning goals with their normal delivery work, so that their deadlines are minimally impacted.

# 6 weeks

## Week 1 - Foundations

- AI fundamentals and concepts
- Intro to GitHub Copilot
- UI tour
- Inline & chat completions
- Use AI to learn about & document an unfamiliar codebase

## Week 2 - Prompting & Context

- Prompting techniques
- Context window
- Tokens vs. premium requests
- Context rot
- Prompt engineering & context engineering
- Copilot instructions file
- Use AI to write e2e tests
- Use AI to first create a plan that it will follow

## Week 3 - Modes & Agents

- Ask, Edit, Agent Mode
- What are agents?
- Working in small batches
- Verification loops
- Begin implementing the upgrade plan

## Week 4 - Customizing GitHub Copilot

- MCP servers
- Working with outside data sources & knowledge
- Custom prompts & agents
- Agent skills
- Security with AI
- When to & when not to use AI
- Finish implementing the upgrade plan

## Week 5 - Bringing Everything Together

- Research Plan Implement
- Use all the knowledge gained so far to implement a new feature
- Spec-driven development
- Using AI to write unit tests
- Tests as guardrails

## Week 6 - Advanced workflows & capstone project

- Agent orchestration
- Subagents
- Hooks
