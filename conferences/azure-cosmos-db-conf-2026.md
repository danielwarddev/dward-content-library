## Session Format

- **Length**: 25-minute technical talks
- **Demo required**: ALL accepted sessions MUST include a live, repeatable demo
- **Format**: On-demand sessions (some featured in the 3-hour live show)

### Every Proposal Must Demonstrate:

1. **A Real Developer Problem** — scale, latency, cost challenges; data modeling or consistency tradeoffs; migration complexity; multi-cloud operational issues; AI challenges (orchestration, vector performance, token/cost efficiency)
2. **A Working Solution** — using Azure Cosmos DB, Azure DocumentDB, OSS DocumentDB, or combinations. Must include architecture/reasoning, SDK usage patterns, tradeoffs/decisions, real code paths and data flows.
3. **A Strong Demo Plan** — live, repeatable demo clearly showing the problem, the solution, and the payoff for developers

## Session Categories / Topics They Want to See

### 1. Intelligent Applications with AI + Azure Cosmos DB/Azure DocumentDB

- Vector search with Azure Cosmos DB
- LLM integration using Microsoft Foundry/Azure OpenAI Service
- RAG architectures using Microsoft Foundry Agent Framework, Semantic Kernel, LangChain, LlamaIndex
- Hybrid operational-and-generative AI patterns
- Building AI applications at scale on multi-cloud or polyglot architectures

### 2. Design Patterns & Best Practices

- NoSQL data modeling for efficiency
- Partitioning for scalability
- Multi-region for availability
- Performance tuning and cost optimization
- Observability and debugging patterns

### 3. Moving Workloads, Modernizing Applications, and Data Migration

- Migrating monoliths to cloud-native architectures
- Refactoring unscalable relational applications
- Migration strategies, tooling, and schema transitions
- ETL flows and downtime mitigation approaches
- Reducing operational complexity while improving global performance
- Lessons learned and common pitfalls from real-world migrations
- Migrating from open-source DocumentDB engines to managed Azure DocumentDB or Azure Cosmos DB

### 4. Multi-Cloud, Cross-Cloud & Hybrid Architectures

- Multi-cloud deployments
- Hybrid scenarios
- Cloud portability or cloud neutrality strategies
- Interoperable data and API patterns
- Real examples: tradeoffs, complexity, and lessons learned

### 5. Innovative Real-World Use Cases

- Detailed technical stories where Cosmos DB solves a real engineering challenge
- Must articulate: the problem, the architecture, the implementation (live demo), the lesson
- Example categories: high-volume transactional systems, real-time detection pipelines, search/discovery/personalization, customer-facing GenAI features, agentic/multi-agent AI systems, healthcare/finance/manufacturing/gaming (with deep technical detail)

### 6. Developer Tools, SDKs & Productivity

- Deep dives into: Python, Node.js, Java, .NET, Rust, Go
- VS Code workflows and debugging
- GitHub-based CI/CD and automation
- Azure Data Studio extensions
- OSS tooling and frameworks supporting DocumentDB workloads

## Suggested Topic Areas (from website)

- **Data modeling and partitioning** — Designing for scale, hot partition avoidance, hierarchical partition keys, access patterns
- **Performance and cost** — RU optimization, indexing strategies, query tuning, troubleshooting latency
- **Reliability and global scale** — Multi-region strategies, change feed patterns, backup/restore, incident readiness
- **AI app patterns** — Chat history, contextual memory, RAG patterns, vector search usage

## What They Value in Submissions

- **Audience-first**: Be explicit about what attendees will learn, who it's for, and what they can apply immediately
- **Real-world stories**: Honest lessons learned and tradeoffs that shaped architecture decisions
- **Practical**: Hands-on demos and specific guidance resonate most
- **Experience-driven talks make the biggest impact**: Decisions you made, problems you hit, what surprised you, what you'd do differently

## Conference Size / Vibe

- **6th annual event** — well-established, Microsoft-backed
- **Free virtual event** — global reach, "thousands of developers worldwide"
- **3-hour live show** + additional on-demand sessions
- **~30 sessions per year** (based on YouTube playlists from 2023-2025)
- **Community + Microsoft mix** — sessions from both Microsoft engineers and community experts
- **Technical depth expected** — "repeatable engineering patterns, not conceptual descriptions"
- **Demo-driven** — every talk must show real architecture, real code, real decisions

## Fit Assessment Notes

This is a **highly specialized, product-focused** conference. Talks must center on Azure Cosmos DB, Azure DocumentDB, or OSS DocumentDB. General cloud/database talks won't fit unless they specifically demonstrate Cosmos DB usage. The emphasis on demos and real-world problem-solving means abstract/conceptual submissions will likely be rejected.
