## Understanding 2-Day Workshops

### What Makes Workshops Different from Talks

| Aspect               | 60-min Talk         | 2-Day Workshop                         |
| -------------------- | ------------------- | -------------------------------------- |
| **Duration**         | 60 minutes          | ~14-16 hours (2 days)                  |
| **Content Depth**    | Overview + demo     | Deep mastery                           |
| **Hands-On**         | Maybe a demo        | Extensive exercises                    |
| **Materials**        | Slides, maybe repo  | Workbooks, repos, exercises, solutions |
| **Attendee Outcome** | "I learned about X" | "I can now DO X"                       |
| **Prep Time**        | Days-weeks          | Weeks-months                           |

### Typical 2-Day Workshop Structure

**Day 1 (7-8 hours):**

- Morning: Foundations, concepts, setup
- Afternoon: Core exercises, building blocks

**Day 2 (7-8 hours):**

- Morning: Advanced patterns, complex scenarios
- Afternoon: Real-world project, troubleshooting, Q&A

## Example Workshop Abstract

Here's a draft if you go with the testing workshop:

---

**Title:** Mastering .NET Testing: From Unit Tests to Container-Based Integration Testing

**Abstract:**

Your test suite should give you confidence, not anxiety. Yet many .NET teams struggle with tests that are either too brittle to trust or too slow to run frequently. This 2-day hands-on workshop will transform how you approach testing in C#.

We'll start with xUnit fundamentals and quickly progress to advanced patterns like parameterized theories, proper fixture management, and parallel test execution. You'll learn mocking strategies that make tests readable and maintainable, and we'll uncover whether your tests are actually testing what you think with mutation testing using Stryker.

Day 2 tackles the hard problem: integration testing. We'll explore why SQLite and in-memory databases often give false confidence, then dive deep into TestContainers—running real databases in Docker for tests that match production behavior. By workshop's end, you'll implement contract testing with Pact to validate service boundaries without brittle end-to-end tests.

**What you'll learn:**

- Advanced xUnit patterns (theories, fixtures, parallelism)
- Effective mocking strategies with Moq and NSubstitute
- Mutation testing to verify test quality
- TestContainers for database integration tests
- Contract testing with Pact for microservices
- Building a test strategy for your specific architecture

**Prerequisites:**

- Working knowledge of C# and .NET
- Basic experience with unit testing
- Docker installed on your machine
